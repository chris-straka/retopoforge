# retopoforge: research on loops at joints, poles, thin limbs, flips, symmetry

Date: 2026-11-13. Read-only research (web + GitHub API; nothing downloaded,
built or changed). Licences were read from each repo's LICENSE file or the
GitHub licence API on this date unless marked "unverified".

Licence tags used below:

- (a) idea we can reimplement clean-room in Rust from the paper
- (b) code with a permissive licence (MIT, BSD, Apache; MPL-2.0 noted as
  file-level weak copyleft)
- (c) GPL / AGPL code: run as a black-box rival, never copy
- (d) non-commercial, region-limited, or no licence at all: measure
  against only, never adopt

Every paper is (a) as an idea. The tag after "code" is about the code.

What retopoforge already has (so the ideas below build on it, not around
it): `--guides` (soft field alignment within 6 edge lengths), joint rings
from rigforge landmarks via `bench/rings.py` (fed in as soft guides),
`--symmetry` (cross-field symmetrization only, not the integer layout),
`--skeleton` (density at creases), `--features` (AlignU/AlignV: UV
equality without integer pins), hard dihedral edges (full U/V integer
pins), dipole insertion, one-shot rounding plus coverage retry. Already
tried and rejected: true greedy rounding, scheduled rounding
(`docs/mils-rounding-scope.md`), a post-rounding untangle stage
(`docs/untangle-verdict.md`). Per-edge integer pins on many feature edges
over-constrain the cover (`docs/corner-marks.md`).

## 1. Quad remeshing quality and robustness

**Instant Field-Aligned Meshes (Instant Meshes)**: Jakob, Tarini, Panozzo,
Sorkine-Hornung. SIGGRAPH Asia 2015, ACM TOG 34(6).
Idea: local smoothing of an orientation field and a position field
(extrinsic, rounding done locally per vertex), very fast and robust, but
no global integer consistency, so it makes many poles and T-junction-like
defects and can merge thin parts.
Paper: https://igl.ethz.ch/projects/instant-meshes/
Code: https://github.com/wjakob/instant-meshes, BSD 3-clause text plus an
"Enhancements" paragraph (read from LICENSE.txt). Tag (b). Last push 2022.
Binaries: see section 6.

**QuadriFlow: A Scalable and Robust Method for Quadrangulation**: Huang,
Zhou, Niessner, Shewchuk, Guibas. SGP 2018, CGF 37(5).
Idea: Instant Meshes' position field, then a global min-cost-flow (or
max-flow) on the integer offsets so that no edge collapses to zero length
and the result is watertight; optional SAT pass removes flips in the
integer offsets. The flow constraint is the relevant part for thin limbs.
Paper: http://stanford.edu/~jingweih/papers/quadriflow/quadriflow.pdf
Code: https://github.com/hjwdzh/QuadriFlow, BSD 3-clause style (LICENSE.txt,
36 lines, read). Tag (b). Flags `-mcf`, `-sharp`, `-sat`.

**Reliable Feature-Line Driven Quad-Remeshing (QuadWild)**: Pietroni,
Nuvoli, Alderighi, Cignoni, Tarini. SIGGRAPH 2021, ACM TOG 40(4).
Idea: trace field-aligned curves from singularities and feature lines,
make a patch layout in which every feature line is a patch boundary, then
quantize patch side lengths with an ILP and fill each patch with a quad
grid. All quads, features exactly on edges.
Paper: DOI 10.1145/3450626.3459941
Code: https://github.com/nicopietroni/quadwild, GPL-3.0. Tag (c). Needs
Gurobi; no binaries.

**Min-Deviation-Flow in Bi-directed Graphs for T-Mesh Quantization
(Bi-MDF)**: Heistermann, Warnett, Bommes. SIGGRAPH 2023, ACM TOG 42(4).
Idea: the integer-length problem of a T-mesh / patch layout is a flow in
a bi-directed graph; solve it exactly by iterative refinement, about 200x
faster than QuadWild's ILP and 11% lower energy. Arc lengths stay
non-negative by construction, so nothing collapses into fold-overs.
Paper: https://cgg.unibe.ch/publication/011282/ (DOI 10.1145/3592437)
Code: solver https://github.com/cgg-bern/libSatsuma, MIT (README and repo
licence). Tag (b), but its optional Blossom-V dependency is not free;
build without it. QuadWild fork: https://github.com/cgg-bern/quadwild-bimdf,
GPL-3.0. Tag (c). This fork is what `bench/quadwild.py` already runs.

**Quad Mesh Quantization Without a T-Mesh**: Coudert-Osmont, Desobry,
Heistermann, Bommes, Ray, Sokolov. SGP 2024, CGF 43(1).
Idea: do the quantization on a decimated copy of the surface instead of
tracing a T-mesh; same guarantees, simpler to implement and easier to add
free boundaries and feature-curve networks. Probably the simplest robust
quantizer to port.
Paper: https://cgg.unibe.ch/publication/011288/ (DOI 10.1111/cgf.14928)
Code: no official repo found. Tag (a).

**Quad Layouts via Constrained T-Mesh Quantization**: Lyon, Campen,
Kobbelt. Eurographics 2021, CGF 40(2).
Idea: quantize a T-mesh with an ILP under a user bound on how far layout
edges may turn from prescribed directions; conforming layouts with
bounded angle error. Shows how to add arbitrary linear constraints
(such as "this curve is a layout edge") to a quantizer.
Paper: https://graphics.rwth-aachen.de/publication/03330
Code: none found. Tag (a).

**Quantized Global Parametrization (QGP)**: Campen, Bommes, Kobbelt.
SIGGRAPH Asia 2015, ACM TOG 34(6).
Idea: show that direct and greedy rounding cannot guarantee a valid
integer-grid map; instead trace a motorcycle-graph T-mesh from the
continuous map and quantize its arc lengths with constraints that rule
out degenerate (folded or collapsed) layouts. The foundation of the
robust family (Bi-MDF, 2024 above).
Paper: https://history.siggraph.org/?p=210403
Code: none public. Tag (a). The 3D sequel (Brueckler, Bommes, Campen,
SIGGRAPH 2022) has code https://github.com/HendrikBrueckler/QGP3D, GPL-3.0
(c), volume only but shows the construction.

**Robust Field-aligned Global Parametrization**: Myles, Pietroni, Zorin.
SIGGRAPH 2014, ACM TOG 33(4).
Idea: allow T-junction-free "motorcycle" patches with integer constraints
only where needed; guarantees a valid map on hard inputs at the cost of
some extra irregular vertices. Tag (a). No public code found.

**Mixed-Integer Quadrangulation (MIQ)**: Bommes, Zimmer, Kobbelt.
SIGGRAPH 2009, ACM TOG 28(3). DOI 10.1145/1531326.1531383.
Idea: cross field with integer matchings, cut graph, seamless map solved
with greedy rounding (round the variable closest to an integer, re-solve,
repeat). Feature edges get "u or v is an integer here" constraints: this
is the mechanism retopoforge's ConstraintU/V already ports. Tag (a).
Code: CoMISo (https://github.com/libigl/CoMISo mirror, GPL-3.0, (c));
libigl's `miq` wraps it (libigl core is MPL-2.0, its CoMISo bits GPL).

**Integer-Grid Maps for Reliable Quad Meshing (IGM)**: Bommes, Campen,
Ebke, Alliez, Kobbelt. SIGGRAPH 2013, ACM TOG 32(4).
Idea: conditions under which a map yields a valid quad mesh, local
injectivity constraints during the solve, and singularities forced to
integer points. Tag (a). Paper: https://hal.archives-ouvertes.fr/hal-00862648

**QEx: Robust Quad Mesh Extraction**: Ebke, Bommes, Campen, Kobbelt.
SIGGRAPH Asia 2013, ACM TOG 32(6).
Idea: extract a valid quad mesh even when the map has small fold-overs
and degenerate triangles, by tracing in the parameter domain with exact
predicates. Directly about flipped faces at extraction.
Code: https://github.com/hcebke/libQEx, GPL-3.0. Tag (c). Idea (a).

**Exact Constraint Satisfaction for Truly Seamless Parametrization**:
Mandad, Campen. Eurographics 2019, CGF 38(2).
Idea: make seams and integer constraints hold exactly (rational
arithmetic) after the float solve, so extraction never meets almost-equal
seam coordinates. Tag (a). No code found.

**Seamless Parametrization in Penner Coordinates**: Capouellez, Zorin.
SIGGRAPH 2024, ACM TOG 43(4).
Idea: optimize an intrinsic metric (Penner coordinates) so any cone set
gives a seamless, locally injective map; very robust on bad meshes.
Paper: https://arxiv.org/abs/2407.21342
Code: https://github.com/rjc8237/penner-optimization, GPL-3.0. Tag (c).

**Feature-Aligned Parametrization in Penner Coordinates**: Capouellez,
Singh, Heistermann, Bommes, Zorin. SIGGRAPH 2025, ACM TOG 44(4).
Idea: the same, with the map exactly aligned to a given feature set
(intrinsic refinement where the input triangles do not allow it). The
most robust current way to make curves exact isolines in a seamless map,
though it is seamless, not yet quantized.
Paper: https://cims.nyu.edu/gcl/papers/2025-Penner.pdf (DOI 10.1145/3731216)
Code: https://github.com/rjc8237/feature-aligned-penner, NO licence file
(all rights reserved). Tag (d).

**Surface Quadrilateral Meshing from Integrable Odeco Fields**: Couplet,
Chemin, Bommes, Chien. SGP 2026 (arXiv 2604.03889).
Idea: optimize integrable, shear-free frame fields (odeco tensors) with
feature alignment and sizing, so the field itself is closer to a valid
parametrization. Tag (a). No code link found.

**NeurCross**: Dong, Wen, Xu, Chen, Zhou, Xin, Tu, Komura, Wang.
SIGGRAPH 2025, ACM TOG 44(4).
Idea: jointly fit a neural SDF and a cross field (SIREN + U-Net), so the
field follows principal curvature robustly on noisy surfaces; then libigl
seamless param + libQEx. Interesting for noisy AI meshes, but needs a GPU
training loop per shape.
Paper: https://arxiv.org/abs/2405.13745
Code: https://github.com/QiujieDong/NeurCross, AGPL-3.0. Tag (c).

**QuadMixer**: Nuvoli, Hernandez, Esperanca, Scateni, Cignoni, Pietroni.
SIGGRAPH Asia 2019, ACM TOG 38(6).
Idea: boolean two quad meshes and re-patch only near the cut curves,
keeping both layouts. Useful later for "replace only the joint region".
Code: https://github.com/stefanonuvoli/quadmixer, GPL-3.0. Tag (c).

**Directional** (library, Vaxman et al.): field design, seamless
integration with integer rounding, meshing. MPL-2.0 per file headers
(no root LICENSE). https://github.com/avaxman/Directional. Tag (b,
weak copyleft per file); still prefer clean-room.

## 2. Deformation-aware and animation-aware quad meshing

Short answer: there is no current paper that takes a skeleton and
produces automatic quad remeshes with guaranteed loops at joints. The
pieces exist separately.

**Quadrangulation of Non-Rigid Objects using Deformation Metrics**: Zhou,
Campen, Zorin, Tu, Silva. Computer Aided Geometric Design 2018
(DOI 10.1016/j.cagd.2018.03.003).
Idea: from several key poses, build a worst-case ("extremal") metric per
point and remesh with that anisotropic sizing and orientation, so the
mesh is not undersampled in any pose. Joints get more, better-oriented
quads; it costs some extra irregular vertices.
Paper: https://cims.nyu.edu/gcl/papers/zhou2018quadrangulation.pdf
Code: none found. Tag (a). Fits our `bench/deform.py` poses directly.

**Quad meshing of articulated shapes via skeleton**: Wu, Liu. J. Advanced
Mechanical Design, Systems and Manufacturing 6(3), 2012.
Idea: split the shape by its skeleton into tubes and joints; tubes get
sweep (ring) quads along the bone, joint regions get a cross field
interpolated from the neighbouring tube directions. Exactly the
"loops ring each limb" structure, but crude at branch points.
Paper: https://www.jstage.jst.go.jp/article/jamdsm/6/3/6_3_354/_article
Tag (a).

**Face Extrusion Quad Meshes (FEQ)**: Pandey, Baerentzen, Singh. SIGGRAPH
2022. Idea: model quad meshes as sequences of face-loop operations
(extrude, bridge, collapse), which yields a skeleton and loop structure
for free. Inspiration for a "sweep along bone" template, not a remesher.
https://www.dgp.toronto.edu/projects/feq/ . Code: listed, no link. (a).

**Single Edge Collapse Quad-Dominant Mesh Reduction**: Knodt. SIGGRAPH
2025, ACM TOG 44(4) art. 145 (arXiv 2411.16874).
Idea: decimation that keeps quads, with per-edge quadric weights that
preserve symmetry and joint (skin-weight) influences; validated by
skinned animation. A decimation route, not a remesher, but its "weight
edges by joint influence" idea is cheap to borrow. Code: none found. (a).

**Sketch-Based Generation and Editing of Quad Meshes**: Takayama, Panozzo,
Sorkine-Hornung, Sorkine-Hornung. SIGGRAPH 2013, ACM TOG 32(4).
Idea: the user draws patch boundaries (loops, rings) and the tool fills
each patch with a quad grid; edge loops are where the artist put them.
Paper: https://la.disneyresearch.com/wp-content/uploads/Sketch-Based-Generation-and-Editing-of-Quad-Meshes-Paper.pdf
Code: not found on GitHub (licence unverified). Tag (a). Already named in
`docs/direction.md` for the patch back end.

**Interactively Controlled Quad Remeshing of High Resolution 3D Models**:
Ebke, Schmidt, Campen, Kobbelt. SIGGRAPH Asia 2016, ACM TOG 35(6).
Idea: on a 2M-face input, the user adds guiding constraints, moves
singularities and connects singularities, all as constraints in an
integer-grid map solve that updates interactively. Closest to "keep poles
off the elbow" as a formal operation. Code: none public. Tag (a).
Paper: https://www.graphics.rwth-aachen.de/media/papers/esck2016_300dpi.pdf

**Dual Loops Meshing** (Campen, Bommes, Kobbelt, SIGGRAPH 2012) and **Dual
Strip Weaving** (Campen, Kobbelt, SIGGRAPH Asia 2014): build the layout
from crossing loops on the surface (the dual), so loops are the primary
object; Dual Strip Weaving lets a user place loops interactively. Tag (a).
https://graphics.rwth-aachen.de/publication/3/campen_2012_sg_preprint1.pdf

### Learned / generative mesh models (do any give loops?)

- **QuadGPT** (Liu et al., HKUST + Tencent Hunyuan, ICLR 2026,

- **PolyFlow** (Tencent, arXiv 2606.30673, Jun 2026): flow-matching

- **DeepMesh** (Zhao et al., 2025, https://github.com/zhaorw02/DeepMesh):

- **Meshtron** (NVIDIA, arXiv 2412.09548, 2024): up to 64k faces,

Verdict: none of these produce skeleton-aware loops, none accept a 2M
triangle hero mesh and return 5k-15k quads with guarantees, and the only
quad-native ones have no code. Measure against them only if code appears.

## 3. Forcing an edge loop along a given closed curve

Known mechanisms, in order of how well they fit our pipeline:

1. **Curve as an integer isoline in the seamless map** (MIQ 2009 feature
   constraints, IGM 2013, Ebke 2016 guiding constraints, Feature-aligned
   Penner 2025 for the robust version). Embed the curve in the working
   mesh (split triangles so the ring lies on edges; a joint ring from
   `bench/rings.py` is a plane cut, so this is exact and cheap). Hard-align
   the cross field to the curve tangent on the ring faces. In the cover,
   make the across-ring coordinate equal on all ring vertices (respecting
   seam transitions) and tie it to ONE integer variable per ring. The
   existing AlignU/AlignV path already gives the equality; the new part is
   a single shared integer per ring instead of per-edge pins (per-edge
   pins are what over-constrained the box cage).
   Preconditions to check, or the constraint is infeasible:
   - Holonomy: the field turns 0 relative to the ring tangent going around
     it (automatic if the field is hard-aligned along the whole ring).
   - Poincare-Hopf: the side of the ring that is a disk (the limb end)
     must hold singularities summing to index +1 (for example four
     valence-3 at the hand/paw), and no singularity may sit on the ring.
     The singularity simplifier must not move singularities across or
     onto a ring.
   - The seam crossing the ring carries an integer translation N = the
     number of quads around the limb. That is the thin-limb knob (see 5).
2. **Curve as a patch boundary** (QuadWild 2021, Takayama 2013, Lyon 2021,
   Coudert-Osmont 2024 with feature networks). Exact by construction, but
   needs the patch/quantization back end.
3. **Cut the mesh along the curve** and solve each side with the cut as a
   boundary-aligned isoline (Lyon et al. 2019 free/aligned boundaries),
   then weld matching counts. Simple, but the two sides must agree on N,
   which is again one shared integer.
4. **Instant Meshes brushes** (orientation and edge brushes): snap the
   position field locally; no guarantee the loop closes.

## 4. Symmetric quad meshing (mirroring the layout, not just positions)

- **Fields on Symmetric Surfaces**: Panozzo, Lipman, Puppo, Zorin. SIGGRAPH
  2012, ACM TOG 31(4). Symmetric N-direction fields from a symmetry map;
  what our `--symmetry` field step already does. Symmetric field does not
  give a symmetric integer layout because rounding and seams break it.
  https://cs.nyu.edu/~dzorin/papers/panozzo2012fss.pdf . (a).
- **Consistent Functional Cross Field Design**: Azencot, Corman, Ben-Chen,
  Ovsjanikov. SIGGRAPH Asia 2017. Consistent fields across a shape or a
  shape pair (functional maps). (a).
- What production tools do (Exoside Quad Remesher, ZRemesher, Blender's
  QuadriFlow symmetry option): bisect on the plane, remesh one half with
  the plane as a boundary, mirror, weld. No paper needed; it gives an
  exactly mirrored layout.
  Clean-room plan for us: cut the working mesh on the detected plane;
  treat the cut as a boundary-aligned isoline (u = integer on it); run the
  pipeline on one half; mirror the extracted half; weld seam vertices
  (counts match because both halves are the same mesh).
  Catch: a singularity on the plane cannot be halved (a valence-3 or
  valence-5 vertex on the plane leaves 1.5 or 2.5 quads per side). The
  simplifier must push plane singularities off the plane into mirrored
  pairs, or keep only even-valence ones (2, 6) on the plane. Also forbid
  the cut graph from running along the plane.
- In-solve alternative (no half-mesh): add equality constraints pairing
  each variable with its mirror image, including integer variables. Harder
  because mirrored seams and matchings must be mapped consistently.

## 5. Rounding strategies that keep thin parts

- **Greedy rounding** (MIQ 2009) and one-shot rounding: no validity
  guarantee; thin parts collapse when an across-limb integer rounds to 0
  or the around-limb count rounds too low. Already measured here: greedy
  and scheduled rounding both made things worse.
- **QGP 2015, Myles 2014, Bi-MDF 2023, Coudert-Osmont 2024**: quantize a
  layout (T-mesh or decimated surface) with arc lengths constrained
  non-negative and loops constrained non-collapsing; Bi-MDF solves it
  exactly as a flow, fast. These are the methods that keep thin parts by
  construction. Lower bounds per arc (>= 1) or per loop (>= k) are plain
  linear constraints in the flow.
- **QuadriFlow 2018**: same idea on Instant Meshes' position field
  offsets via min-cost flow; cheaper, local, proves the point that flow
  constraints stop collapse.
- **Cheap version in our current back end**: for each joint ring, the
  integer translation N on the seam that crosses it is the quad count
  around the limb. Bound it below (for example N >= 6, or a value from
  limb radius / target edge length, never under 4) when rounding, by
  clamping that integer and re-solving the continuous part. One bounded
  integer per ring, not a new rounding scheme, so it does not conflict
  with the earlier negative results.

## 7. Ranking: top 5 ideas for loops at joints, fewer poles near joints,
## kept thin limbs, fewer flips, at a fixed triangle budget

1. **Joint rings as hard integer isolines (one integer per ring).**
   Sources: MIQ 2009 feature constraints, IGM 2013, Ebke 2016, Takayama
   2013 (the goal), Feature-aligned Penner 2025 (robust version).
   Helps: loops at joints (directly), poles near joints (indirectly, the
   precondition check forces them off the ring).
   What changes: working mesh (embed the ring polyline as edges: a plane
   cut, cheap); field (hard alignment on ring faces instead of soft
   6-edge guides); cover (AlignU/V equality along the ring plus one shared
   integer, seam transitions handled); rounding (round ring integers
   first, then the rest as today); extraction unchanged.
   Difficulty: medium. Hard part is seams crossing the ring and the
   infeasible cases (singularity on the ring, wrong index on the limb
   side); needs a fallback to today's soft guide when the check fails.

2. **Pole-free joint bands in the singularity simplifier, with a
   bone-aligned field on limb segments.**
   Sources: Wu & Liu 2012 (tube sweep fields), Ebke 2016 (singularity
   repositioning), Zhou 2018 (deformation metric), Poincare-Hopf
   bookkeeping above.
   Helps: poles near joints (directly), loops at joints (a band with no
   singularities and a bone-aligned field closes its isolines into rings).
   What changes: field (bone direction as a hard or strong constraint on
   limb faces from `--skeleton`); singularity simplifier (forbidden band of
   a few edge lengths around each ring; move or cancel singularities out
   of it, toward the limb end or the body); dipole placement must also
   skip the band. Rounding and extraction unchanged.
   Difficulty: low to medium. All inside existing stages; risk is
   pushing poles into the shoulder/hip, which then needs a metric.

3. **Minimum quad count around each limb ring (bounded integer).**
   Sources: QuadriFlow 2018 and Bi-MDF 2023 (flow lower bounds), QGP 2015.
   Helps: thin limbs kept (tails, fingers of monsters, antennae), fewer
   flips on thin parts (a collapsed limb is where folds cluster).
   What changes: rounding only (clamp the seam translation integer that
   crosses each ring to N >= N_min, re-solve continuous), plus an
   automatic ring on thin tubes even without a rigged joint (detect thin
   tubes by local diameter vs target edge length). Depends on idea 1's
   ring bookkeeping.
   Difficulty: low once 1 exists; medium alone.

4. **Robust quantization back end (Bi-MDF flow, or the T-mesh-free 2024
   method) with rings and features as layout constraints.**
   Sources: QGP 2015, Bi-MDF 2023 (libSatsuma is MIT, so even its code is
   usable as a reference; still port clean-room to stay Rust-only),
   Coudert-Osmont 2024, Lyon 2021 for constraints.
   Helps: flips (valid layout by construction), thin limbs everywhere,
   all-quad output, worst-case surface error (QuadWild's measured edge);
   rings become exact patch boundaries.
   What changes: replaces rounding and extraction (trace a layout or
   decimate, solve the flow, fill patches); field and simplifier stay.
   This is the already-planned `--backend patch`.
   Difficulty: high. The biggest item; the 2024 decimation variant
   avoids T-mesh tracing, which is where most of QuadWild's fragility is.

5. **Exactly symmetric layout by half-solve, mirror and weld.**
   Sources: Panozzo 2012 (field), production practice (Exoside, ZRemesher,
   Blender QuadriFlow symmetry).
   Helps: left/right symmetric layout (exact), halves the chance of a pole
   landing on one elbow only; makes ring results identical on both sides.
   What changes: pipeline wrapper (cut on plane, run one half, mirror,
   weld); cover (plane as a boundary-aligned isoline); simplifier (no
   odd-valence singularity on the plane, no seam along it).
